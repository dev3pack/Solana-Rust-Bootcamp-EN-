# ex06 — Enums and `match`

**Goal:** model a fixed set of instruction shapes and handle every case.

## Concepts

- An enum is a value that is one of several variants.
- Variants can be struct-like (`Transfer { ... }`), tuple-like (`Close(String)`),
  or carry no data at all.
- `match` selects a branch and binds the data inside the variant.
- `match` must be exhaustive: every variant needs an arm.
- `..` ignores the remaining fields of a struct-like variant.
- Returning `&str` from a function that borrows an `Instruction` is safe because
  the returned reference points into the instruction.

## What to implement

Open `src/ex06.rs`. The `Instruction` enum is already defined.

| Function | What it should do |
| --- | --- |
| `kind(ix)` | Return `"transfer"`, `"create"`, or `"close"` |
| `lamports_moved(ix)` | Return the lamports for `Transfer`, otherwise `0` |
| `account_touched(ix)` | Return the sender, the new address, or the closed address |

## Worked example

```rust
enum Shape {
    Circle(f64),
    Square { side: f64 },
}

fn area(shape: &Shape) -> f64 {
    match shape {
        Shape::Circle(radius) => 3.14159 * radius * radius,
        Shape::Square { side } => side * side,
    }
}
```

There is no `_` arm because both variants are covered. If you add a `Triangle`
variant later, this function stops compiling until you handle it. That is the
feature, not the bug.

## Hints

- In `kind`, use `Instruction::Transfer { .. } => "transfer"` and similar arms.
- In `lamports_moved`, bind the field with
  `Instruction::Transfer { lamports, .. } => *lamports`. The field is borrowed,
  so dereference it to return a `u64`.
- In `account_touched`, bind `from`, `address`, or the tuple field and return it
  directly. The compiler infers the lifetime from the single input reference.
- Do not use `_` in `kind` or `account_touched`; part of the exercise is naming
  every variant.

## Tests

`cargo test --test ex06`

There are four tests:

1. the transfer kind
2. the create and close kinds
3. only transfer moves lamports
4. every variant has a main account
