# ex07 — `Result` and `?`

**Goal:** report expected failures without panicking, and propagate them with
the `?` operator.

## Concepts

- `Result<T, E>` is `Ok(T)` or `Err(E)`.
- `Ok(())` means "success with no value".
- A custom error enum can carry data, such as the available and required
  amounts.
- `?` returns the error early if the result is `Err`; otherwise it unwraps the
  `Ok` value.
- `?` only works inside a function that returns a compatible `Result`.
- On Solana, an error reverts the transaction's state changes, but the
  transaction still pays its fee.

## What to implement

Open `src/ex07.rs`. `TransferError` is already defined.

| Function | What it should do |
| --- | --- |
| `validate(from, to, amount)` | Reject zero amounts, then self-transfers |
| `transfer(balance, from, to, amount)` | Validate, check funds, return the remaining balance |
| `pay(balance, from, to, amount)` | Call `transfer` and propagate with `?` |

Validation order matters:

1. `amount == 0` → `ZeroAmount`
2. `from == to` → `SameAccount`
3. `amount > balance` → `InsufficientFunds { available, required }`
4. otherwise `Ok`

## Worked example

```rust
fn half(n: u64) -> Result<u64, String> {
    if n % 2 != 0 {
        return Err(String::from("odd number"));
    }
    Ok(n / 2)
}

fn quarter(n: u64) -> Result<u64, String> {
    let half = half(n)?;
    Ok(half / 2)
}
```

If `half(n)` returns `Err`, `quarter` returns that same error immediately. If it
returns `Ok`, the value is bound to `half` and execution continues.

## Hints

- `validate` does not need the balance. It only looks at the names and amount.
- In `transfer`, call `validate(from, to, amount)?;` before the balance check.
- Return `Err(TransferError::InsufficientFunds { available: balance, required: amount })`.
- `pay` can be two lines: call `transfer(...)?`, then return `Ok(remaining)`.
- Do not use `unwrap()` or `expect()` in these functions. The tests check the
  error values.
