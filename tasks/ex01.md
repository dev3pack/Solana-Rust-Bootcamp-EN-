# ex01 — Variables and Types

**Goal:** learn how Rust declares values, when a value can change, and why money
uses `u64`.

## Concepts

- `let` is immutable by default.
- `let mut` opts into mutation.
- Shadowing creates a new variable with the same name.
- `const` is a value fixed at compile time.
- `u64` is an unsigned 64-bit integer. It cannot be negative.
- Integer division drops the remainder.
- `1_000_000_000` is the same number as `1000000000`; underscores are for humans.

## What to implement

Open `src/ex01.rs` and replace each `todo!()`.

| Function | What it should do |
| --- | --- |
| `sol_to_lamports(sol)` | Multiply whole SOL by `LAMPORTS_PER_SOL` |
| `lamports_to_sol(lamports)` | Divide lamports by `LAMPORTS_PER_SOL`, dropping the remainder |
| `apply_bonus(balance, bonus)` | Add the bonus and return the new balance |
| `double(value)` | Return twice the value, using shadowing |
| `is_empty(balance)` | Return `true` only when the balance is zero |

`LAMPORTS_PER_SOL` is already defined for you. Do not change its value.

## Worked example

This is a different function, so you can see the shape without copying the
answer:

```rust
let price = 10;          // immutable
let mut count = 0;       // mutable
count += 1;
let count = count * 3;   // shadowing: a new variable
```

`count` is now `3`. The first `count` still exists conceptually, but the name
now refers to the new one.

## Hints

- `LAMPORTS_PER_SOL` is a `u64`, so multiply a `u64` by it.
- `/` between two integers truncates: `7 / 2` is `3`.
- For `double`, write `let value = value * 2;` and then return `value`. That is
  shadowing, not mutation.
- For `is_empty`, a comparison such as `balance == 0` already produces a `bool`.
  You do not need an `if`.
