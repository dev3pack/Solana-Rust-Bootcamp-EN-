# ex08 — Capstone: Mini Bank

**Goal:** combine a struct, `impl`, a `Vec<String>` history, and `Result` into
one small account.

This is the capstone. It uses only what you learned in ex01 to ex07.

## Rules

- **No `HashMap`.** The history is a `Vec<String>`.
- **No traits.** Do not add an `Auditable` trait or any other trait.
- **No panics for expected failures.** Return `Result`.
- Keep the history format exact; the tests compare the strings.

## What to implement

Open `src/ex08.rs`. `BankError` and `BankAccount` are already defined.

| Method | What it should do |
| --- | --- |
| `BankAccount::new(owner)` | Create an account with zero lamports and an empty history |
| `deposit(amount)` | Reject zero; add lamports; push `"deposit <amount>"` |
| `withdraw(amount)` | Reject zero and overdrafts; subtract lamports; push `"withdraw <amount>"` |
| `balance_in_sol()` | Return whole SOL, dropping the remainder |

The history entries are exactly:

```text
deposit 500
withdraw 200
```

Use `format!("deposit {amount}")` and `format!("withdraw {amount}")`. No colons,
no extra words.

## Worked example

```rust
let mut history: Vec<String> = Vec::new();
let amount = 500;
history.push(format!("deposit {amount}"));
assert_eq!(history, vec![String::from("deposit 500")]);
```

`format!` returns a `String`. The vector owns it, so the history outlives the
local `amount`.

## A session

```rust
let mut account = BankAccount::new("alice");
account.deposit(500)?;      // balance 500, history ["deposit 500"]
account.withdraw(200)?;     // balance 300, history ["deposit 500", "withdraw 200"]
account.withdraw(600)?;     // Err(InsufficientFunds { available: 300, required: 600 })
```

After the failed withdrawal, the balance is still 300 and the history still has
two entries. A rejected operation changes nothing.

## Hints

- `new` takes `&str`; use `owner.to_string()` to create the owned field.
- `Vec::new()` creates an empty history.
- In `deposit`, check `amount == 0` first. Then add and push.
- In `withdraw`, check zero first, then compare `amount` with `self.lamports`.
  Only mutate after both checks pass.
- `balance_in_sol` divides by `1_000_000_000`, just like ex05.
- The tests use `assert_eq!` on `Result`, so the error values and the history
  strings must match exactly.

## Tests

`cargo test --test ex08`

There are four tests:

1. a new account is empty
2. a deposit updates balance and history; zero is rejected
3. a withdrawal updates balance and history
4. an overdraft is rejected without changing state
